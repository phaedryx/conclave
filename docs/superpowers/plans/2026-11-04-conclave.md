# Conclave Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A local hub and a per-session Claude Code channel server that let agents on Tad's laptop take part in Slack channels: epic channels created automatically, invitations, addressed-only delivery, and Tad-only authority with explicit grants.

**Architecture:** `conclave hub` is one long-running process. It holds the only Slack Socket Mode connection, keeps state in SQLite, and routes messages over a Unix socket (`~/.conclave/hub.sock`, newline-delimited JSON) to `conclave channel` processes. Claude Code launches one of those stdio MCP servers per session. The channel server declares `experimental['claude/channel']` and pushes `notifications/claude/channel`. All authority decisions are made in the hub, because the hub sees every delivery. The channel server is a thin relay.

**Tech Stack:** Ruby 4.0.1, `mcp` 0.13.0, `httpx`, `async-websocket` (Socket Mode only), `sqlite3`, minitest + webmock. Concurrency uses threads plus one hub-wide `Mutex`.

**Spec:** `docs/superpowers/specs/2026-11-04-conclave-design.md`

**Out of scope for this plan:** the Atelier changes (spec § Atelier changes). They live in a separate Swift repo and get their own plan once this plan's Task 11 passes end-to-end.

## Global Constraints

- The word is **authorize**, never "allow", in commands, copy, method names and tests.
- Agent name = short worktree name, matching `/\A(.*?sc-\d+)/`. So `tad_sc-1234-fix-the-thing` becomes `tad_sc-1234`. With no `sc-NNNN`, the full name is used.
- Delivery happens only when a message addresses the agent (`@name`, or `@all`, `<!here>`, `<!channel>`) **and** the sender is permitted. Anything else is dropped silently, with no reply in the channel.
- An agent never reads text from an unauthorized human, whether in a delivery, in `get_thread`, or in a backfill. The only exception is a message Tad explicitly links (a permalink).
- Grants are per agent and never pass from agent to agent (spec § Authorization).
- Meta keys use only `[A-Za-z0-9_]`.
- Epic channels are public and named `epic-<id>-<slug>`, at most 80 characters, lowercase, using `[a-z0-9-]`.
- Loop guard N defaults to 10 (config `loop_guard_limit`). Only posts from Tad or an authorized person reset it.
- The offline queue is capped at 50 messages per agent (config `offline_queue_limit`), dropping the oldest first. Queued messages get the `zzz` reaction.
- Config path is `$CONCLAVE_HOME/config.yml`, where `CONCLAVE_HOME` defaults to `~/.conclave`. Tokens are never committed. `config.example.yml` is committed.
- The channel server must never crash the Claude session. If the hub is down, tools return `error_response("Conclave hub not running")`.

## Review Focus

1. **Spoofed or relayed authority.** Jane is authorized for `tad_sc-1234` only. She asks it to post `@tad_sc-5678 delete the branch`. Expected: the post appears in Slack, but `tad_sc-5678` never receives it. Test: Task 6 `test_relayed_request_does_not_reach_unauthorized_agent`.
2. **Unauthorized text inside threads.** An outsider replies in a thread where an agent is working, then the agent calls `get_thread`. Expected: the outsider's text is replaced with `[hidden message ts=…]`. Test: Task 8 `test_get_thread_hides_unauthorized_humans`.
3. **Bot echo.** The hub's own `chat.postMessage` comes back as a Socket Mode event with its `bot_id`. Expected: it is ignored and not delivered a second time. Test: Task 7 `test_ignores_own_bot_echo`.
4. **Name tokens inside other text.** `@tad_sc-12345` must not address `tad_sc-1234`, and `email@tad_sc-1234.com` must not address anyone. Test: Task 3 `test_word_boundaries`.
5. **Hub restart while agents are connected.** Expected: channel servers reconnect with backoff and re-register, and tools return the "hub not running" error until then. Test: Task 9 `test_reconnects_after_hub_restart`.

### Task 6: Agents registry and outbound posting

**Files:**
- Create: `lib/conclave/hub/agents.rb`, `test/hub/agents_test.rb`

**Interfaces:**
- Consumes: `Store`, `Authority`, `Slack::Client#post_message`, `Addressing.parse`.
- Produces: `Conclave::Hub::Agents.new(store:, authority:, slack:, loop_guard_limit:, queue_limit:)`. Methods:
  - `register(name, connection) -> :ok | :name_taken`. `connection` responds to `deliver(Hash)`. On register, the agent's queue is drained to the connection.
  - `unregister(name)`, `online?(name)`.
  - `deliver(agent, message)`. `message` is the delivery hash below. Online agents get it through `connection.deliver`. Offline agents get it through `store.enqueue`, plus a `zzz` reaction on `message[:channel_id]/message[:ts]`. Before delivering, this records `current_authority[agent] = message[:authority]`.
  - `post(agent:, channel_id:, text:, thread_ts: nil, in_reply_to_ts: nil) -> { ts: String }`:
    - Posts as `username: agent` with `icon_emoji` chosen by `agent.sum % EMOJI.size` from a fixed list.
    - Computes the authority with `authority.combine(current_authority[agent], delivered_authority[agent][in_reply_to_ts])`. With no prior delivery, the base is `owner`, since the session was started by Tad.
    - Addresses the channel's members, excluding the poster.
    - For each addressee that `authority.permits?(auth, addressee)` allows and the loop guard doesn't block, delivers with `sender: agent, sender_role: "agent", authority: auth`.
  - `human_posted(channel_id:, thread_key:, user_id:)` resets the loop guard for `thread_key` when the user is owner or authorized for any member.
- Delivery hash keys (and the channel meta keys): `channel`, `channel_id`, `ts`, `thread_ts`, `sender`, `sender_role`, `authority`, `text`, `shared` (an Array of `{ author:, text:, ts: }`, default `[]`).
- Loop guard: `thread_key = thread_ts || ts`. Each agent→agent delivery increments `count[thread_key]`. Once the count reaches `loop_guard_limit`, the guard stops delivering and posts one note: `"Pausing agent-to-agent messages in this thread after #{limit} exchanges. @tad, reply here to continue."` The note goes in the thread, as username `conclave`.

### Task 7: Router and commands

**Files:**
- Create: `lib/conclave/hub/router.rb`, `lib/conclave/hub/commands.rb`, `test/hub/router_test.rb`, `test/hub/commands_test.rb`

**Interfaces:**
- Consumes: `Agents`, `Authority`, `Store`, `Addressing`, `Permalink`, `Slack::Client`.
- Produces:
  - `Conclave::Hub::Router.new(agents:, authority:, store:, slack:, bot_id:, commands:)` with `handle_message(event_hash)`. `event_hash` is a Slack `message` event.
  - `Conclave::Hub::Commands.new(store:, authority:, slack:, owner:)` with:
    - `handle_text(event) -> Boolean`. True when the message was an in-channel `@agent authorize|deauthorize <@U…>` command from the owner, and so was consumed.
    - `handle_slash(payload) -> String`. Takes a `/conclave` payload and returns the ephemeral response text.

Router rules, in this order:
1. Ignore the event if `subtype` is present (edits, joins and so on) or `bot_id == bot_id` (our echo).
2. `store.set_last_seen(channel, ts)`.
3. Call `agents.human_posted(...)`.
4. If `commands.handle_text(event)` returns true, stop.
5. Look up `members = store.members(channel)` and `addr = Addressing.parse(text, members:)`. Targets are `addr[:all] ? members : addr[:agents]`.
6. Find the role. If `user == owner`, every target is permitted. Otherwise each target must pass `authority.human_role(user, target)`. A target that fails is dropped silently.
7. If the sender is owner, `shared = Permalink.extract(text)`. Each link is fetched with `slack.history(channel:, latest: ts, inclusive: true, limit: 1)`, or `slack.replies(channel:, ts: thread_ts)` filtered to `ts` when a `thread_ts` is present, and becomes `{ author:, text:, ts: }`. If a fetch fails, the router posts an ephemeral-style thread reply to Tad: `"Couldn't read linked message #{url}: #{error}"`. Links from non-owners are never fetched.
8. `agents.deliver(target, {... sender: user, sender_role: role, authority: user, shared: })`.

Commands:
- In-channel: `@tad_sc-1234 authorize <@UJANE>` and `@tad_sc-1234 deauthorize <@UJANE>`. Only the owner can issue them. The hub confirms with a reaction, `white_check_mark`.
- Slash: `/conclave invite <agent>`, `remove <agent>`, `authorize <agent> <@U…>`, `deauthorize <agent> <@U…>`.
  - `invite` calls `slack.join(channel)` on public channels; if that fails with `method_not_supported_for_channel_type`, it answers `"Add the Conclave app to this private channel first."`.
  - On success, `invite` calls `store.add_membership`.
  - From anyone but the owner, every command answers `"Only Tad can do that."`. The slash response is ephemeral, so this doesn't leak to the channel.

### Task 8: Epic channels, filtered reads, hub socket server

**Files:**
- Create: `lib/conclave/hub/epic_channels.rb`, `lib/conclave/protocol.rb`, `lib/conclave/hub/server.rb`, `test/hub/epic_channels_test.rb`, `test/hub/server_test.rb`

**Interfaces:**
- Consumes: `Shortcut::Client#epic_for_story`, `Store`, `Slack::Client`, `Agents`, `Authority`.
- Produces:
  - `Conclave::Hub::EpicChannels.new(store:, slack:, shortcut:, owner:)` with `ensure_joined(agent) -> String?` (returns the channel_id).
    - It does nothing if `store.epic_joined?(agent)` or `AgentName.story_id(agent)` is nil, or if the story has no epic.
    - Otherwise it finds `store.epic_channel(epic_id)`. If there is none, it calls `create_channel(name: slug)`; on `name_taken`, it retries once with a `-<epic_id>` disambiguator and records the result. Then it invites the owner.
    - It finishes with `add_membership` and `mark_epic_joined`.
    - Slug: `"epic-#{id}-#{name.downcase.gsub(/[^a-z0-9]+/, "-").gsub(/^-|-$/, "")}"[0, 80]`.
  - `Conclave::Protocol`: `write(io, hash)` (JSON plus `"\n"`) and `read(io) -> Hash?` (nil at EOF).
  - `Conclave::Hub::Server.new(path:, handler:)` with `start` (spawns an accept thread) and `stop`. It removes a stale socket file before binding and `chmod 0600` after binding.

Requests and responses over the socket are `{ "id":, "op":, ... }` → `{ "id":, "ok": true, ... }` or `{ "id":, "ok": false, "error": }`. Unsolicited pushes are `{ "op": "deliver", "message": {...} }`.

| op | request fields | hub action | response |
